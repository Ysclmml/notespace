# ADR-0005：普通本地编辑器的精简边界

- 状态：Accepted
- 日期：2026-08-30
- 取代范围：ADR-0001 中尚未落地的可信宿主门禁，以及 ADR-0004 中复杂修复、隔离和恢复机制

## 背景

产品是单用户、本地优先的 Markdown 编辑器。此前的 Phase 0 设计预先引入了 HMAC/nonce、可信宿主证据、隔离区、持久化操作日志、37 个未来 IPC 命令、14 项 feature flag 和超大传输压力门禁。这些机制没有解决当前用户的编辑需求，却显著增加了代码量、协作成本和失败面。

真实需求只有三类与数据可靠性直接相关的问题：误粘贴大型 Base64 不能卡死界面；截图应落盘而不是写入正文；保存失败不能破坏原文件。

## 决策

1. 应用运行时固定为 **React + TypeScript + CodeMirror 6 + Tauri 2 + Rust**。Node 只负责前端构建、测试和轻量仓库检查；活动工作流不使用 Ruby。
2. 不再设置独立的 Phase 0 安全认证门。产品功能可以按纵向切片直接实现和验证。
3. IPC 只为当前已经实现的命令定义小型、可读的 serde/TypeScript 类型；禁止预冻结未来命令全集。
4. MVP 不实现 HMAC、nonce、可信事件、path-swap manifest、quarantine、repair token、持久化 Save-As journal、复杂 crash recovery、通用 feature flag registry 或 193 MiB WebView 传输门禁。
5. 只保留以下三项产品护栏：
   - **Base64 防卡死**：大段粘贴文本在进入 CodeMirror transaction 前检查；文件在 Rust 端用固定缓冲预检。大型 data-image 或病态长行显示简单阻止页，正文不进入 WebView。
   - **截图落盘**：图片先写入文档相邻的 `assets/`，成功后才插入相对 Markdown 链接；失败不改变正文。
   - **原子保存**：同目录临时文件写入、flush（可 sync）后 rename；失败时原文件保持完整。
6. 大文件是性能降级问题，不是安全事件。普通多行大文档可进入 source-only 模式；MVP 不建设 mmap 或分块编辑器。
7. 外部修改最多先采用简单 mtime/revision 提示；复杂冲突合并、崩溃恢复、资产 GC 和跨平台边界加固按真实需求后置。

## 最低验证

- 大型 data-image 文本粘贴后正文与 Undo 历史不变。
- 同类文件打开时正文不返回前端。
- 约 10 MiB 的普通多行 Markdown 可在 source-only 模式打开和保存。
- 截图成功后存在图片文件和相对链接；写入失败时正文不变。
- 原子保存故障时旧文件完整，成功时新文件完整。

## 后果

代码和文档围绕用户可见纵向切片组织，后续功能需要时再引入对应接口。Git 历史保留已删除实验作为参考，但任何代理都不得仅因旧任务文档或旧提交存在而恢复这些机制；若未来确有威胁模型或发布需求，必须用新的 ADR 和实测证据重新提出。
