# ADR-0015：可靠截图粘贴与每工作区图片位置

- 状态：Accepted
- 日期：2026-09-03
- 修订：ADR-0005 固定文档相邻 `assets/` 的图片存储位置；ADR-0011 固定本地资源 scope 导致隐藏目录或外部卷图片不可见的限制
- 保持不变：本地文件为真相、图片先落盘后插链接、Base64 前置阻断、正常编辑事务与 Undo、原子文档保存

## 背景

用户反馈截图软件已把图片写入剪贴板，但 Markdown 无法粘贴；并要求截图默认放在 Markdown 所在目录，或由每个工作区独立指定目录。不同原生剪贴板提供者在 WebKit 中可能暴露 `items`、`files`、只有 MIME 类型或空载荷，不能仅凭 `getAsFile()` 判断是否为图片。右键粘贴也必须经过相同的编辑器路径。

## 决策

1. 可视与源码表面统一识别图片表示。PNG/TIFF 等明确图片可触发原生读取；没有可用文字或文件的 Files-only/空表示可尝试原生 fallback。普通文本、HTML、URI 和已暴露的非图片文件不被图片路径吞掉。
2. Rust 读取剪贴板像素，在 macOS 优先直接读取 PNG，保留 arboard 的 TIFF/跨平台读取。图片解码与编码在后台执行；最大 3200 万像素。图片数据不经过 IPC，也不写入 Markdown Base64。
3. 默认将 PNG 写到该篇 Markdown 的父目录；每个工作区根右键提供双语“图片保存位置…”，可改为一个现存绝对目录。工作区归属使用最长匹配根，独立文件仍默认同目录。失效/不可写自定义目录必须报错，不悄悄换目录。
4. 设置只保存路径或 null 到已有工作区便利状态，null/缺省表示文档同目录。各根独立、关闭和重开可保留；选择取消不变，修改不迁移旧图片，也不修改旧 Markdown。未打开根、正文和剪贴板内容均不新增持久化副本。
5. PNG 使用唯一名称与 `create_new`，避免覆盖；同卷返回正确百分号编码的相对 URI，跨卷无法相对引用时使用文件 URI。写入完成后编辑器才以可撤销事务插入链接；失败、取消或来源文档变化不插入，Undo 不删除图片文件。
6. 未命名文档先检查剪贴板有图，再请求 Save As。取消不写图；成功后绑定原 Tab 迁移后的文档，将插图交给新编辑表面的普通事务，保留 Undo。当前表面/正文/来源所有权不再匹配时拒绝迟到结果，不向后来打开的同名文档插入。
7. 右键粘贴将正文交给编辑器 paste 事件，从而复用 Base64 阻断、解析和 Undo。空剪贴板不能用空文字替换选区；原生事件与 fallback 不能重复插入。
8. 对实际显示的本地图片，先规范化并确认是现存支持图片文件，再仅授权该文件给 Tauri asset 协议。图片节点与查看器在准备成功后加载，更新/卸载后忽略迟到结果。静态 scope 不扩大到任意目录；远程图片不新增探测、抓取或上传。

## 验证

- 合成 PNG、TIFF/Files-only 前端元数据；macOS 独立命名剪贴板的 PNG 读取；不访问真实用户剪贴板。
- 临时目录中的默认/自定义位置、Unicode/空格/标点 URI、尺寸上限、失败清理、不覆盖、失效目录与本地图片授权路径。
- 多根与嵌套根隔离、偏好保存/恢复、对话框取消及双语菜单。
- Save As 成功/取消/无图、双表面的插图与 Undo、StrictMode、来源切换/编辑/卸载后的迟到保护；普通文字与大型内嵌图片粘贴不回归。
- 用户实际截图软件与安装包仍需 macOS 原生验收；PNG-only 合成用例不能单独证明用户故障根因，因为系统可能自动合成 TIFF 表示。
