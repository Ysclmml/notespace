# ADR-0026：数学分隔符兼容与跨表面一致渲染

- 状态：Accepted
- 日期：2026-09-04
- 取代范围：取代 `EDIT-MATH-001` 的 Deferred 状态，并补充 ADR-0006 的可视/源码往返、ADR-0017 的分享 HTML/PDF 与 ADR-0022/0025 的移动阅读渲染范围。

## 背景

真实 Markdown 笔记中的数学内容不只使用 remark-math 的美元分隔符。LaTeX、MathJax 和大量知识库也常用 `\(...\)` 表示行内公式、`\[...\]` 表示块公式。若编辑器只识别 `$...$` 与 `$$...$$`，CommonMark 会把反斜线当作普通转义，导致合法公式在可视模式显示成方括号文本；这属于产品兼容缺陷，不能要求用户先改写全部笔记。

数学同时存在于桌面可视编辑、移动只读渲染和可分享 HTML/PDF。只修一个表面会让同一 Markdown 在多端含义不同，也可能在可视编辑后把原公式序列化为普通文本。

## 决策

### 支持的写法

- 普通 Markdown 同时接受 `$...$`、`$$...$$`、`\(...\)` 与 `\[...\]`。前两种保持 remark-math 原语义；圆括号为行内数学，方括号为显示数学。
- `\(...\)` 不跨越换行；未闭合或不成对的分隔符不生成数学节点，按 CommonMark 普通转义文字显示。仅查看时权威 Markdown 字节不变；用户实际进行可视编辑后，普通转义可随既有 serializer 规范化。`\[...\]` 可包含多行；分隔符独占行时保持正常块结构，同一行写法也提升为显示公式，而不是悄悄降为行内样式。
- 解析前先用 Markdown 语法树识别受保护源区间，再只规范化安全正文中的成对 TeX 分隔符。围栏/缩进代码、行内代码、原始 HTML、链接、图片、定义和已有数学节点中的相似字符保持字面量；禁止用全局正则替换整篇源文。

### 桌面编辑往返

- Milkdown/Crepe 收到的初始正文和后续源码切回/外部干净重载都使用同一数学规范化投影，因此四种写法进入可视模式后都成为真实数学节点。
- 仅打开、查看或切换表面不得把投影写回正文、标记 dirty 或改变磁盘字节；未编辑保存仍为零差异。用户首次真正进行可视修改后，serializer 可把 TeX 分隔符规范化为等价的 `$`/`$$`，但不得退化成方括号普通文本或改变公式体。
- 源码模式继续显示权威 Markdown，不在后台批量迁移工作区文件。无效 KaTeX 保留可编辑源码并显示局部回退，不能拖垮整篇文档或阻断其他正文编辑。

### 移动阅读与分享导出

- 移动端使用相同分隔符规范化和 remark-math AST，只把数学节点交给固定 KaTeX 渲染；原始 HTML 仍按文本处理，KaTeX 禁止受信任 HTML/URL 扩展。解析或排版失败时局部显示原公式字面量，不使阅读页崩溃。
- HTML 导出从最新 Markdown 快照解析四种分隔符，以 KaTeX 生成 script-free MathML。公式不依赖 CDN、JavaScript、NoteSpace 或外部字体，继续满足 ADR-0017 的单文件离线分享与 CSP；macOS PDF 复用同一 HTML，因此公式仍是可选择的结构化内容而非截图。
- 数学处理不读取额外文件、不联网、不上传正文，也不改变现有图片、Mermaid、正文和最终文件预算。手机应用更新继续 Deferred，本决策不增加下载、安装或热更新能力。

## 验证

- 解析器覆盖四种分隔符、中文上下文、下标/上标/常见命令、未闭合分隔符、同行显示公式和既有美元公式不变。
- 代码围栏、缩进代码、行内代码、HTML、链接/图片目标、定义以及现有数学内部的分隔符样文本必须保持原样。
- 桌面真实 Crepe 测试覆盖 `\(...\)`/`\[...\]` 初始渲染、源码切回和外部正文更新；只查看/切换不 dirty，首次可视编辑后的 Markdown 仍包含等价数学节点。
- 移动测试检查四种公式生成 KaTeX/MathML、错误局部回退、无脚本/原始 HTML 执行；离线快照复用同一正文渲染。
- HTML/PDF 导出检查四种公式、代码保护、无效公式回退、CSP 无脚本、单文件无外部样式/字体，并保持输入正文不变。

## 结果

用户可以直接打开来自 LaTeX、MathJax 或美元语法生态的常见数学笔记，不需要先迁移分隔符。代价是一层有语法边界的解析规范化以及移动/导出的 KaTeX 运行依赖；它只构建可重建投影，不改变 Markdown 作为唯一持久化真相，也不引入工作区批量改写。
