# ADR-0007：本地文件、多工作区与双栏预览

- 状态：Accepted
- 日期：2026-08-30
- 修订：ADR-0005 中仅以 Markdown 为当前可编辑文件的范围，以及 ADR-0006 中单一主画布的导航范围
- 保持不变：ADR-0005 的精简本地应用边界和三项实用护栏；ADR-0006 的 Markdown 可视/源码双表面

## 背景

实际使用不只是在一个目录内连续编辑 Markdown。文档经常引用同仓库的 Python、Rust、JSON 等代码或配置文件；用户也会同时阅读多个工作区、临时打开一个独立文件，并希望像浏览器一样在主 Tab、临时浮层和右侧分栏之间选择。只读、单工作区模型已经不能覆盖这些日常路径。

与此同时，这仍是单用户、本地优先的普通文本编辑器。扩展文件和工作区能力不应引入项目数据库、后台服务、插件框架、复杂会话恢复或新的安全平台。

## 决策

### 1. Markdown 与普通文本分别使用合适的编辑表面

- `.md`、`.markdown` 继续使用 ADR-0006 定义的 Milkdown/ProseMirror 可视编辑和显式 CodeMirror 源码模式。
- Rust 文件层识别的 UTF-8 文本、代码和配置文件使用 CodeMirror 6 直接编辑，不进入 Milkdown，不提供无意义的“可视/源码”切换。
- 第一批常见后缀至少覆盖纯文本、JSON/YAML/TOML、Python、JavaScript/TypeScript、CSS/HTML、Rust、Java、C/C++、C#、Go、Shell、SQL、Ruby、PHP、Swift、Kotlin、Lua、Dart、Scala、Groovy、Perl、Protocol Buffers 和 GraphQL；识别表由 Rust 文件层集中维护。
- 新建 Markdown 和新建文本先建立内存中的未命名 `DocumentSession`。首次保存或“另存为”通过原生文件选择器确定路径，再把该 session 及所有引用它的 Tab/历史条目原子迁移到新路径。
- 已有文件保存与另存为都复用 ADR-0005 的同目录临时文件、flush/sync、rename 语义；不另建第二套保存协议。

### 2. 工作区是可切换集合，不是唯一全局根目录

- 一个窗口可以同时保持多个已打开工作区；顶部工作区选择器决定当前侧栏显示哪一个，切换不关闭其他工作区或已打开 Tab。
- Quick Open 聚合所有当前工作区，并在存在多个根目录时显示来源工作区。
- 应用仅在本机设置中保存最近工作区、最近文件、当前打开的工作区路径及活动工作区。启动时尽力恢复；路径不存在或读取失败时跳过，不阻塞其余启动流程。
- 可以打开不属于任何工作区的单个文件；它进入最近文件和 Tab，但不会伪造一个工作区。
- 关闭工作区只从当前窗口集合移除，不删除磁盘文件，也不自动关闭已经打开的文档 Tab。
- 这是轻量便利状态，不是正文真相、崩溃恢复日志或跨设备同步。

### 3. 代码引用提供三种明确去向

- Markdown 中可解析的本地代码引用可以在当前文档附近打开只读浮层、在右侧只读分栏打开，或作为普通可编辑文件进入主 Tab。
- 右侧最多一个辅助栏。打开新的引用替换辅助栏内容；关闭辅助栏不影响主 Tab 和正文状态。MVP 不建设任意网格、拖拽布局或多 Pane 管理框架。
- 浮层和辅助栏使用有界预览并稳定滚动，显示真实行号、目标行高亮、语言、路径、复制和打开文件操作；主 Tab 打开完整文件并由 CodeMirror 负责大文档视口渲染。
- 普通 Markdown 链接仍优先进入应用导航路由，不能被代码引用预览拦截。

### 4. 原生菜单、应用菜单与右键菜单共享动作语义

- macOS 原生菜单默认简体中文，并随应用语言切换为英文；应用顶部菜单和设置入口使用同一动作语义。
- 原生菜单只发出小型、固定的动作 ID，由前端执行新建、打开文件、打开工作区、保存、另存为、设置、视图切换等当前能力；不把应用状态复制进 Rust 菜单层。
- 自定义编辑右键菜单在捕获阶段识别触摸板右键和 Control-click，避免先破坏选区再打开菜单。菜单按目标能力提供撤销/重做、剪切/复制/粘贴/全选，以及链接打开、在新 Tab 打开和复制链接。
- 输入提示和 fenced-code 语言补全是本地编辑辅助，不上传内容、不写入 Markdown，也不进入浏览历史；提示文案跟随 locale。

### 5. 模式切换按语义位置对齐

- Markdown 可视/源码切换继续是用户显式动作。
- 切换时用当前选区附近的正文语义位置映射到另一表面，并保留各表面自己的精确滚动/选择状态；不得每次回到文档顶部。
- 该映射是 best-effort，不承诺 ProseMirror 节点位置与 Markdown 字符 offset 一一相等，但标题、段落、列表和代码附近应落在同一内容区域。

## 不变量

1. Markdown 文件仍是 Markdown 正文的唯一持久化真相；普通代码/文本文件的磁盘文本是各自唯一真相。
2. `DocumentSession != Tab != HistoryEntry`；Save As 迁移 session 身份时必须同步迁移所有 Tab 历史引用，不复制正文。
3. 多工作区不改变内部链接的相对解析根：优先使用包含当前文档的最长匹配工作区。
4. 最近记录只保存路径和顺序，不保存正文、剪贴板、选择内容或文件快照。
5. 浮层和右侧预览只消费文件读取结果；编辑只发生在主 Tab 的 Markdown 或 CodeMirror 表面。
6. 新能力不得恢复账户、网络上传、遥测、通用 feature flag、巨型 IPC schema 或复杂恢复引擎。

## 最低验证

1. 新建 Markdown/文本、编辑、Save As 后，Tab、dirty、后退/前进及同 session 引用都迁移到新路径；磁盘内容正确。
2. 同时打开两个工作区并切换侧栏，两个文件树、Quick Open 来源和已开 Tab 相互独立；重启可恢复仍存在的工作区。
3. 打开独立代码文件可编辑、保存、另存为；常见后缀得到正确语言和真实行号。
4. `path:line` 可分别在滚动浮层、右侧栏和完整文件 Tab 打开；复制返回完整可见预览文本，目标行保持高亮。
5. 中文和英文下，原生菜单、应用菜单、设置与右键菜单的当前动作一致；Mac 触摸板右键一次触发且保留原选区。
6. 可视/源码在长文档中往返后停留在相同语义段落附近，不回到顶部，也不制造 dirty 或导航历史。

## 后果与明确不做

- 产品从 Markdown 专用编辑器扩展为以 Markdown 为中心的本地文本工作台，但不会演变为 IDE：没有编译、运行、LSP、调试、Git 工作台或远程文件系统。
- 多工作区和一个右侧辅助栏满足当前并行阅读需求；任意分屏布局、窗口级会话快照、跨设备最近记录和项目数据库后置。
- 文件选择器取消、失效最近路径和不可读文本都以普通可恢复状态提示，不建设额外安全审批或恢复协议。
