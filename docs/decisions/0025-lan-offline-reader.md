# ADR-0025：普通构建的局域网阅读与移动离线快照

- 状态：Accepted
- 日期：2026-09-04
- 取代范围：取代 ADR-0022 的“生产发布前必须先完成可信配对”门槛、ADR-0023 的 Debug 专用/随机端口/常驻警告，以及 ADR-0024 的 Release 编译隔离。ADR-0022～0024 的真实移动 App、用户显式启停、所选根只读、opaque ID、路径边界、多地址发现、并发和及时停止语义继续有效。

## 背景

当前产品目标明确为让 Android 手机在同一网络中快速浏览电脑上的 Markdown 工作区，而不是构建远程文件管理器。持续显示 Debug、无认证等提示会占用移动端宝贵的顶部空间；桌面每次使用随机端口、手机必须输入完整 `host:port`，也让日常连接显得繁琐。

用户同时希望在电脑暂时离线时继续阅读，并在下次连接后取得电脑磁盘上的新版本。它需要一份由用户明确选择、可完整替换的本机离线投影，而不是把偶然打开过的页面当作不可管理的缓存。

当前阶段明确接受同一局域网内无 TLS、无配对的传输。这个取舍不能取消所选根、只读、路径校验和读取预算，但不再以 Debug 构建、醒目警告或尚未实现的配对流程阻断普通桌面与移动构建。

## 决策

### 普通构建中的局域网阅读

- 局域网阅读成为普通桌面端和 NoteSpace Mobile 构建能力，不再只编译或注册于 Debug。桌面共享命令、HTTP host、mDNS 发布，移动真实 HTTP transport、mDNS 浏览、局域网明文连接所需 CSP 与 Android 网络/多播能力在相应普通构建中可用。
- 共享仍默认停止。只有用户在桌面「移动访问」中明确选择至少一个当前已打开工作区并启动后，服务才监听；停止共享、退出应用或移除共享根立即终止对应访问，不后台常驻。
- 当前传输继续使用 `/api/v1` 的无认证 HTTP/JSON，不增加 TLS、证书、密码、二维码、配对码、bearer token、设备批准或逐设备撤销。多个移动端可以同时读取同一服务。
- 桌面和手机移除占据界面的 Debug/无认证警告卡片与常驻横幅，也不再把正常连接标成 Debug 模式。无认证事实保留在帮助与设计文档中，不以持续提示占用阅读空间。
- 无认证只改变设备身份和传输保密性，不改变数据边界：只返回用户本次所选根内已保存的 Markdown 与授权资源，未保存编辑和绝对路径不进入协议；客户端只使用 opaque ID；根外路径、symlink、隐藏项、重目录、设备文件、不支持类型和超限读取继续拒绝；没有写入、上传、创建、删除、重命名或远程命令接口。
- ADR-0024 的 `activeRequestCount`、多地址探测、磁盘 I/O 不持全局锁、停止取消长任务和重启废弃旧 ID 语义保持不变。该计数仍不是手机在线数量。

### 默认端口与手动连接

- 桌面和手机的局域网阅读默认端口统一为 `49920`。桌面端可在 `1024`～`65535` 范围内修改并持久化；损坏或越界的已存值回退到 `49920`。显式修改只影响下次启动服务，不在运行中悄悄换端口。
- 手机手动连接允许只输入 IPv4、IPv6 或主机名；未提供端口时自动补 `49920`，未提供 scheme 时自动使用当前 HTTP 传输。用户输入了显式端口或完整基址时保留其值。因此桌面使用非默认端口时，手机仍需输入该端口。
- mDNS 继续发布并探测服务实际使用的端口，不依赖两端默认值；自动发现、多个地址候选和手动连接互为补充。Android 模拟器仍可用 `10.0.2.2`，省略端口时同样补 `49920`。

### 逐工作区离线阅读

- 离线保存必须由用户逐工作区明确开启；普通在线浏览不会自动把所有正文永久缓存。手机显示已保存工作区的占用空间和最近同步时间，并允许用户手动更新或清除本地副本。
- 每个离线工作区保存一份完整的 Markdown 投影：工作区/目录导航元数据、Markdown 文档元数据和正文。快照写入移动端 IndexedDB，不写入桌面文件、不成为新的同步真相，也不包含密码、令牌或电脑绝对路径。
- 单个工作区的一次快照最多 `128 MiB`、`5,000` 个目录和 `5,000` 篇 Markdown；在线单篇正文和根边界仍受服务端既有预算约束。超过任一边界、读取不完整或本地写入失败时，本次同步失败并给出可重试状态。
- 同步先构建完整候选，再在一个 IndexedDB 事务中替换当前可用快照；不得逐篇覆盖正在使用的旧版本。成功的新快照反映电脑当前目录增删和磁盘正文，失败、断线、取消或容量不足均保留上一份完整快照。
- 电脑不可达时，浏览、全文搜索和最近阅读可从已保存快照打开；搜索只覆盖该快照内 Markdown 正文。未保存为离线的工作区不伪装可用，联网收藏和资源读取也不从零散缓存推断结果。
- 手机重新连接到对应电脑后，所有仍标记为离线保存的可见工作区自动刷新；用户也可手动刷新。刷新在后台生成候选，不抢走当前阅读位置；只有完整成功后才原子切换到新快照。
- 本轮离线包不保存图片、附件、已渲染 Mermaid 资产或其他资源。Markdown 正文中的 Mermaid 源码仍随正文保存，但离线包不另存渲染产物；依赖电脑资源端点的图片明确显示为未离线，重新联网后按现有只读资源链路加载。

### Android 应用更新方向

- 本轮不实现手机更新器，也不把网页资源热更新作为离线阅读的前置条件。
- 后续直接分发 APK 时，移动端只检查 NoteSpace 固定 GitHub Releases 的稳定版本；发现新版后显示版本和发布说明，由用户确认下载匹配 APK，再交给 Android 系统安装器完成安装。应用不得静默替换自身。
- 可升级 APK 必须保持相同 application ID 并使用稳定、受控的发布签名；签名不一致时明确失败，不能用清数据或降级安装绕过。
- 不采用 JavaScript/HTML 运行时代码热更新。它会引入 Web 资源与 native/Rust 版本兼容、签名和回滚的第二套发布协议，当前收益不足以覆盖复杂度。
- 将来通过 Google Play 分发时，更新入口切换为 Play In-App Updates，并遵循商店签名与发布轨道；不让 GitHub APK 安装器和 Play 更新同时竞争同一安装来源。

## 验证

- Debug 与普通 Release 构建都应包含受控的局域网共享/发现能力；桌面和手机均无 Debug/无认证常驻提示，但共享默认关闭、空根不能启动、停止/退出及时收敛。
- 默认端口为 `49920`；桌面设置在 `1024`、`65535` 和重启后保持，越界回退；手机 host-only、显式端口、完整 URL、IPv4/IPv6/主机名与 mDNS 实际端口均有契约测试。
- 离线测试覆盖用户逐工作区开启/清除、占用空间与最近同步时间、IndexedDB 恢复、断网目录/正文/搜索/最近、成功重连刷新、电脑端新增/修改/删除、失败保留旧快照，以及 `128 MiB`、`5,000` 目录、`5,000` 文档边界。
- 原子性测试必须证明读取不完整、断线、取消、配额或事务失败不会发布半份快照；图片、附件及 Mermaid 渲染资产没有进入离线存储。
- 本轮包不得宣称已具备手机自动更新；后续更新器验收另覆盖固定 GitHub 来源、用户确认、系统安装器、稳定签名和 Play 分发切换。

## 结果

局域网阅读从一次 Debug 联调能力变成可以日常使用的普通构建能力：默认端口让大多数手动连接只需输入电脑地址，离线工作区让手机在电脑不在线时仍能完整浏览文字内容，并在重连后安全替换为最新磁盘快照。

代价是当前阶段不提供传输加密或设备授权，同网设备在用户开启服务期间可以读取所选内容；这是本阶段明确接受的产品取舍。数据面仍被限制在显式启动、所选根、只读、opaque ID、路径校验和固定预算内。移动更新另以系统安装器/商店机制推进，不把热更新复杂度混入离线阅读。
