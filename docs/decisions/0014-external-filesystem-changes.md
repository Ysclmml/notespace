# ADR-0014：外部文件变化与受保护的重载/保存

- 状态：Accepted
- 日期：2026-09-03
- 依据：用户明确要求同步其他应用在磁盘上新增、修改和删除的工作区文件。
- 修订：外部修改提示后置的产品范围；当前基线升为 1.1。
- 保持不变：ADR-0005 的精简本地应用边界、三项实用护栏，以及 ADR-0012/0013 的共享正文、独立视图和无正文快照原则。

## 背景

文件树和已打开正文只在应用内操作时刷新，会漏掉其他编辑器或系统文件管理器产生的变化。直接重新打开全部文件则会浪费读取、丢失本地草稿，或让迟到读取/保存影响已经关闭后重开的同名文件。需要增加轻量磁盘通知和版本检查，而不是文件同步服务、自动合并或通用恢复引擎。

## 决策

### 1. 只监听当前窗口相关路径

- Rust 使用固定版本 `notify 8.2.0`，对已打开工作区根递归监听；未被根覆盖的独立文件监听其父目录，使用非递归模式以支持原子替换和删除/重建。
- 文档范围包含 Tab `current/back/forward` 实际引用的已保存文件，不包含未命名页、仅剩 clean 缓存或已经关闭的文档。工作区关闭不关闭仍打开的文件，其独立监听仍可保留。
- 原生路径事件按 150 ms 窗口合并；前端去重并以 250 ms 静默间隔刷新，连续事件最多等待 1 秒即提交一批。事件只含 `{ paths }`，不携带正文。
- 完成监听配置后先检查一次；重新聚焦/恢复可见时复查，每 30 秒兜底检查并重建监听配置，补偿丢失通知、监听失败、根或父目录删除后重建。清理和后续配置串行，卸载/旧订阅不提交结果或清除新订阅。
- 文件树沿用受支持后缀、每根隐藏项和 symlink 规则。重目录和应用临时保存文件在枚举/事件过滤时排除；显式打开的文件仍可被观察。递归 OS watcher 本身可能仍覆盖被过滤的重目录，不声称完全避免其底层监听开销。

### 2. 文件树更新与文档重载分开处理

- 通知只触发受影响工作区重新枚举；聚焦/兜底检查可刷新全部打开根。新建、删除和目录变化反映在树中，未知后缀仍按既有文件类型规则过滤，不扩大文件能力。
- 每次刷新使用请求版本；迟到成功或失败都不能覆盖更新的隐藏偏好、手动刷新或重新打开的根。根不可用可清空该根树并提示，但不删除内存文档或其他根。
- 外部重命名按“旧路径删除 + 新路径新增”处理，不猜测并迁移 session、修改 Markdown 链接或修复引用。
- `inspect_documents(paths)` 只返回磁盘状态/版本元数据。版本未变不读正文；确实变化且 session 干净时才使用现有 `open_document` 预检读取。
- 成功重载更新共享 session，不新建 Tab、组或历史访问，不夺取焦点；各 Tab 视图保持，必要时根据新的 `sourceOnly/text` 分类统一强制源码表面。过期正文/版本、正在保存、原引用已关闭或已迁移的结果不得覆盖当前页。

### 3. 冲突保留内存正文，由用户选择

- dirty 文档遇到磁盘变化时不自动读取覆盖；缺失、不可读或预检 blocked 时，无论原本是否 dirty，都保留内存正文与原 dirty 状态，并显示中英文提示条。
- 提示条存在时暂停该文档普通手动保存和自动保存，避免无意覆盖磁盘或把已删除文件重新创建。用户仍可编辑本地缓冲区。
- 用户可重载磁盘文件；若将丢弃本地未保存编辑，必须明确确认。确认后的读取仍核对同一轮引用、正文和磁盘基线，期间新编辑不会被覆盖。
- 只有检测到可用新版本的 `modified` 文档可选择覆盖磁盘；此动作始终先确认，并用用户看到的外部版本作为保存前提。磁盘再次变化时再次提示，不能无条件强写。
- `missing` 文档只提供 Save As，不自动重建原路径。文件以原版本重新出现时可清除提示而保留草稿；其他状态可重试读取或 Save As。Save As 的现有原生目标确认和不覆盖其他已打开文档规则保持。

### 4. 磁盘版本是轻量基线，不是锁

- 原生 editable open 和成功 save 结果返回 `diskRevision`；它由高分辨率 mtime、大小与可用的平台文件身份信息组成，不计算或传输正文摘要。TypeScript 字段为可选，仅保持 Demo/旧测试 adapter 兼容，正常原生流程有版本。
- 已打开文档保存使用 `save_document(path, content, expectedRevision?)`。有前提版本时，Rust 在写入前和临时文件 rename 前各检查一次；不一致或文件缺失返回外部变化错误，保留旧文件和 dirty。
- 同目录临时文件写入/flush/sync/rename 的原子保存保持；保存返回所写文件句柄的版本，不误取之后被其他应用再次替换的路径版本。
- 这是 best-effort 外部修改保护，不是文件锁或原子 compare-and-swap。检查与 rename 之间仍有极小竞争窗口；不为消除该窗口引入锁服务、prepare/ack、持久 journal 或通用安全平台。
- 手动/自动/覆盖/Save As 继续按文档串行。开始排队写入及完成状态更新时校验原 Tab 所有者（含历史），避免旧保存把后来重开的同名文件标 dirty、误清冲突或触发回写；正常编辑、导航和移组不丢掉仍有原引用的会话。
- 已关闭且无引用的 clean 缓存不拥有正文；重新打开采用新磁盘读取，锚点也按新正文计算。仍被 current/back/forward 引用的共享或 dirty session 不由普通打开静默替换。

### 5. 小型接口与明确边界

新增 `inspect_documents(paths)` 和 `watch_filesystem(workspaceRoots, documentPaths)`，当前 invoke 总数为 16；新增事件 `filesystem-changed: { paths: string[] }`。`watch_filesystem([], [])` 清理订阅，前端 adapter 可选暴露监听能力供 Demo 降级。原生菜单仍只转发既有 13 个 action，不增加菜单状态副本。

不新增正文快照、网络/云同步、自动三方合并、外部重命名跟踪、文件数据库、通用事件总线、崩溃恢复引擎或后台常驻服务。准确自动测试、UI 和打包结果由 `PROJECT_STATE.md` 记录。

## 最低验证

- 合成临时工作区的外部新增/修改/删除、目录变化、隐藏项与重目录过滤；独立文件的原子替换及删除后重建。
- 监听先注册后配置、事件去重/限时合并、聚焦/30 秒兜底、失败重试和 StrictMode/卸载/迟到清理。
- 干净文档自动重载，共享正文/独立位置/无新历史；dirty、缺失、不可读和 blocked 保留缓冲区，重复错误不反复预检同一 blocked 版本。
- 重载/覆盖确认和取消、普通/自动保存暂停、缺失仅 Save As；磁盘恢复原基线后提示可清除且 dirty 不变。
- 本地继续编辑、保存、关闭/同路径重开、Save As 或新树刷新后的迟到结果不覆盖；保存完成不误标新会话 dirty。
- 原生读入版本与内容一致；保存写前/rename 前版本检查及原子写入故障保持旧目标。测试不读取或修改真实用户文档。
