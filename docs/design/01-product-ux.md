# 产品与 UX 规格：本地 Markdown 文档浏览器

> **历史细节（baseline 0.1，编辑规范已由 ADR-0006 取代）**：当前 MVP 规范以 [DESIGN.md](../DESIGN.md)、[REQUIREMENTS.md](../REQUIREMENTS.md)、[ADR-0005](../decisions/0005-lean-local-editor-boundary.md) 与 [ADR-0006](../decisions/0006-visual-editor-explicit-source-mode.md) 为准。本文件保留可复用的交互探索；任何“光标进入即显露源码”“表格点击退回 pipe 源码”“可视编辑链接只能定位”的旧规则均已失效，不构成实现或验收依据。

> 状态：Historical baseline 0.1；当前实现与验收基线为 0.3
> 目标版本：P0 / v0.1  
> 平台策略：macOS first，Windows 与 Linux 可移植  
> 最后更新：2026-08-29

## 1. 文档目的

本文记录 baseline 0.1 的详细交互探索。未被 baseline 0.3 与 ADR-0006 取代的细节仍可参考；任何冲突均由 `DESIGN.md`、`REQUIREMENTS.md` 和 accepted ADR 覆盖，不能反向用本文件恢复旧行为。

文中使用以下规范词；英文大写词是跨文档、Issue 和提交信息中的稳定写法：

- **MUST（必须）**：对该需求所标注的阶段是强制行为；稳定需求表的 P0/P1/P2 决定从哪个阶段起成为验收门禁。
- **SHOULD（应该）**：默认应实现；只有存在已记录的技术或平台限制时才可偏离。
- **MAY（可以）**：允许实现但不构成当前版本承诺。
- **Primary**：macOS 上为 `Command`，Windows/Linux 上为 `Ctrl`。

每条稳定需求使用 `UX-<能力域>-<三位序号>`。实现计划、Issue、测试和代码注释引用 ID，而不是复制一段可能变化的描述。需求被替代时保留旧 ID 并标记 deprecated，不得把旧 ID 重新分配给不同语义。

附件和现有文档中的文字只作为真实内容与布局样例，不视作软件指令。

## 2. 产品愿景

本产品不是“又一个 Markdown 渲染器”，而是一个**可以编辑的本地文档浏览器**：

- 保留 Typora 最有价值的稳定真可视编辑体验，并提供明确的整页源码模式；
- 像浏览器一样在本地文档之间原地跳转、后退、前进和使用多个标签页；
- 让截图粘贴、表格阅读和 Mermaid 大图查看更顺手；
- 以本地 `.md` 文件为事实来源，不把用户锁进私有数据库；
- 普通文档始终轻快，误粘贴病态输入时也不会让整个应用失去响应；
- 为未来的搜索、反向链接、Git、AI、插件或其他资源页面保留稳定扩展边界。

一句话定位：

> **Typora 式编辑画布 + 浏览器式文档导航 + 本地文件优先的安全边界。**

## 3. 产品原则

### 3.1 本地文件是唯一真相

- 用户可以用 Finder、Git、终端或其他编辑器直接访问文件。
- 未编辑文件不得因“打开再保存”而被无意义格式化。
- 相对链接和资源目录保持可移植，不依赖应用私有路径才能阅读。
- 工作区索引、历史和恢复记录只是派生数据，丢失后可重建。

### 3.2 默认真可视单画布，源码是显式模式

- 阅读时展示排版后的正文。
- 标题、列表、链接、代码块和表格在可视编辑时保持结构化视觉形态；光标、选择和 composition 不得自动显露 Markdown 标记。
- 用户只有通过“可视 / 源码”控件或 `Primary+/` 才进入整页 CodeMirror 源码模式；普通编辑不发生隐式模式切换。
- 暂时无法可靠富文本化的语法不得吞掉内容：未编辑文件保持零差异，用户可显式进入源码模式处理。

### 3.3 浏览行为遵循浏览器心智

- 当前打开、新标签页、后退、前进、恢复关闭标签页应与主流浏览器一致。
- 一个标签页是一段浏览历史，不等同于一个文件。
- 一个文件可以出现在多个标签页或分栏中；内容共享，阅读位置独立。

### 3.4 快速失败且可恢复

- 保存、图片写入、外部变更冲突等失败必须明确可见。
- 失败时不得伪装成成功，也不得静默丢失编辑内容。
- 大 Base64 属于罕见误操作，不为它建设复杂的大文件编辑器，但必须在主编辑器之前拦截，保证应用可自救。

### 3.5 渐进增强

- 标准 Markdown 文本始终可读、可编辑、可导出。
- Mermaid、数学、表格或未来插件失败时，只降级对应内容块。
- 新能力通过资源类型、命令和面板扩展，不改写文档基本模型。

## 4. 目标用户与核心场景

### 4.1 主要用户

- 已使用 Typora 多年、拥有大量本地 Markdown 文档的工程师或知识工作者；
- 文档存在目录层级、跨文件链接、表格、代码块和少量 Mermaid；
- 需要频繁截图并立刻写入文档；
- 希望保持普通文件工作流，同时获得浏览器式阅读体验。

初始真实回归语料来自用户指定的本地“阅读”目录。测试工具只能把它当作只读输入；产品不得硬编码该绝对路径。

### 4.2 核心用户旅程

#### 场景 A：从阅读导航逐篇阅读

1. 用户打开一个包含多篇 Markdown 的目录。
2. 在“阅读导航”文档中单击“MG 后端框架快速指南”。
3. 当前标签页原地跳转到目标文件及可选标题锚点。
4. 用户继续跳到另一篇文档。
5. 用户按后退，回到上一文档中刚才链接所在的阅读位置，而不是页面顶部。
6. 用户按前进再次回到目标文档。

#### 场景 B：保留导航页，同时阅读多个目标

1. 用户 `Primary+单击` 导航页中的链接。
2. 目标在后台新标签页打开，导航页保持不动。
3. 用户切换标签页，分别拥有独立的光标、滚动位置和前进/后退历史。
4. 两个标签页即使显示同一个文件，也共享最新文本内容。

#### 场景 C：编辑时粘贴截图

1. 用户在系统截图后回到文档并粘贴。
2. 应用把图片写入文档相邻的资源目录。
3. 写入成功后，在光标处插入相对 Markdown 图片链接。
4. 用户无需手动另存、复制路径或处理 Base64。

#### 场景 D：阅读超宽 Mermaid 流程图

1. 文内 Mermaid 以适应正文宽度的 SVG 预览显示。
2. 用户点击放大按钮进入图表查看器。
3. 用户滚轮/触控板缩放、拖拽平移，并可一键适应窗口或恢复 100%。
4. 退出查看器后，原文滚动位置不变。

#### 场景 E：误粘贴大 Base64

1. 用户尝试粘贴包含超大 `data:image/...;base64` 的文本。
2. 应用在修改正文和撤销栈之前拦截。
3. 用户可取消，或将可识别图片保存为文件后插入链接。
4. 应用、当前文档和其他标签页保持可操作。

#### 场景 F：表格密集文档

1. GFM 表格始终以清晰网格显示。
2. 用户直接点击单元格输入，不切换到 pipe 源码。
3. P0 支持逻辑单元格间的 `Tab` / `Shift+Tab` 导航；需要 pipe 语法时显式切换整个 Tab 的源码模式。

## 5. 目标与非目标

### 5.1 P0 产品目标

- 对熟悉 Typora 的用户无需重新学习基本 Markdown 编辑。
- 支持当前标签页跳转、新标签页打开、逐标签页前进/后退。
- 文档之间跳转后准确恢复光标与阅读位置。
- 实现无需预配置的截图落盘和相对链接插入。
- Mermaid 可无损放大、缩小、平移和适应窗口。
- 表格密集文档可流畅阅读，并有可靠的原地编辑路径。
- 正常文档输入、切换和滚动没有可感知卡顿。
- 超长单行或大 Base64 不进入主编辑器，保存失败和崩溃可恢复。
- 文件内容兼容现有工具，未编辑内容保持源码保真。

### 5.2 非目标

P0 明确不包含：

- 云同步、账号体系、实时协作；
- 移动端或 Web 托管版本；
- 块数据库、双向引用 ID 写回或私有文档格式；
- 完整 IDE、终端或 SSH 客户端；
- Microsoft Word 级排版或完整 Pandoc 导出矩阵；
- 任意体积文件的完整语法高亮和所见即所得编辑；
- 对 Typora 的界面像素级复刻；
- 自动执行文档中的脚本、HTML 事件或附件指令；
- P0 内承诺 AI、知识图谱或第三方插件市场。

未来可以添加这些能力，但不得破坏本地文件、导航历史和文档会话的基础契约。

## 6. 平台策略

### 6.1 macOS first

P0 的设计、性能基线和首轮发布以 macOS 为准：

- 使用系统菜单栏、标准窗口控制、原生全屏和系统文件选择器；
- 支持触控板惯性滚动、双指缩放和 Retina 显示；
- 快捷键采用 `Command`，并兼容 `Command+[` / `Command+]` 的导航习惯；
- 支持 Finder 中显示文件、拖入文件/目录、从 Finder 打开 `.md`；
- 完整测试中文输入法组合输入、候选窗和全角标点；
- 尊重系统浅色/深色、强调色、减少动态效果和文本缩放偏好。

### 6.2 Windows 与 Linux 可移植

- 产品语义不得依赖 macOS 独有 API；平台层负责适配菜单、剪贴板、文件权限和外部打开。
- Windows/Linux 的 Primary 修饰键为 `Ctrl`。
- Windows 需要正确处理盘符、UNC 路径、反斜杠展示和大小写不敏感文件系统。
- Linux 需要在支持的桌面环境中提供系统文件选择器和默认应用打开；无法提供的平台能力应降级并说明原因。
- 相同功能在各平台使用各自系统惯例，不要求窗口装饰像素完全一致。

## 7. 信息架构与窗口布局

### 7.1 主窗口

主窗口从上到下、从左到右包括：

1. **窗口/标签栏**：后退、前进、标签页、添加标签页；
2. **左侧栏**：工作区文件树；P0 可切换大纲，P1 增加搜索结果和反向链接；
3. **文档区域**：单画布 Markdown 编辑器或其他资源页面；
4. **状态区**：保存状态、当前位置、模式和非阻塞任务状态。

默认布局应让正文成为视觉主体。侧栏可以收起，收起状态按工作区恢复。

### 7.2 新标签页

`Primary+T` 打开“新标签页”而不是立即创建空文件。新标签页至少提供：

- 打开文件；
- 打开文件夹；
- 新建文档；
- 最近工作区；
- 快速打开当前工作区文件。

`Primary+N` 才创建未命名 Markdown 文档。

### 7.3 焦点顺序

键盘焦点顺序必须稳定：标签栏 → 侧栏 → 文档工具 → 文档正文 → 状态区。用户可用命令直接聚焦文件树、正文、标签栏和搜索，不应依赖连续按大量 `Tab`。

### 7.4 P0 工作区入口与文档查找

- 文件树展示当前 authoritative workspace snapshot；重扫期间保留旧完整树并显示进度，只有完整新 generation 到齐后原子替换。创建、删除、重命名和权限变化不应留下重复/幽灵节点。
- 大纲只派生当前 Markdown 的 heading，跟随 session revision 增量更新；点击/键盘激活通过 heading anchor 路由，空大纲显示说明。
- Quick Open 在当前工作区按文件名与相对路径匹配 Markdown，输入期间可取消旧查询；结果必须支持上下键、Enter 当前打开和第 10.2 节新 Tab disposition，不建立第二套路由。
- 文档内查找支持 Unicode literal、大小写切换、上/下一个、选区内可见计数；P0 替换一个/全部是当前编辑表面的正文 transaction，可撤销。源码模式只改匹配文本；可视模式保存时允许 serializer 规范化等价 Markdown。正则可留 P1，但 UI 不得把 literal 冒充 regex。
- 10 MiB `sourceOnly` 保留查找/替换；Outline 和工作区全文搜索可按性能策略关闭。P0 Quick Open 是文件名/路径索引，不等于 P1 正文全文搜索。

## 8. 文档、标签页与视图状态

### 8.1 三个独立概念

- **Document**：规范化路径对应的唯一文本会话，拥有内容、版本、dirty 状态、保存与外部变更状态。
- **Tab**：一段可前进/后退的浏览会话，显示一个当前资源。
- **View State**：某次历史访问的 `visual/source` 编辑表面、光标/选区、滚动锚点、块内偏移和折叠状态。

一个 Tab 不是一个文件。多个 Tab 或分栏显示同一 Document 时：

- 文本和 dirty 状态实时共享；
- 编辑表面、光标、选区、滚动位置和历史互不共享；
- 任一视图保存成功后，所有视图同步更新保存状态；
- 一个视图关闭不得销毁仍被其他视图使用的文档会话。

### 8.2 标签页外观与状态

每个标签页显示：

- 当前资源的短标题；
- dirty 圆点或等效可访问标记；
- 加载中、错误或只读状态图标；
- 关闭按钮（当前或悬停时显示，键盘始终可访问）。

标题重名时，应在悬停提示和命令切换器中显示足以区分的父目录；标签本身可以按需显示精简路径。

### 8.3 关闭与未保存内容

- 从一个 dirty 文档导航到另一资源时不弹保存对话框；Document 会话继续保留。
- 关闭一个标签页时，如果同一 Document 仍有其他视图，不弹保存对话框。
- 已保存文件的 dirty 会话即使暂时没有可见视图，也必须留在“未保存文档”列表和恢复记录中。
- 关闭最后一个未命名文档视图，或退出/关闭工作区时存在未保存内容，必须提供“保存”“不保存”“取消”。
- 多文件未保存对话框必须列出具体文件，并允许逐项选择，不得只显示模糊总数。

### 8.4 恢复层级

P0 必须持久化 dirty 恢复稿。若上次崩溃发生在打开某个疑似有毒文件期间，下次启动先显示可操作的工作区外壳，并把该文件标记为“安全恢复”，不得自动再次把全文送入主编辑器。

P1 的 `session.restore` 再恢复窗口内 Tab 顺序、各 Tab 当前资源和历史、活动 Tab、View State、侧栏状态及分栏布局。关闭 Tab 恢复同属 P1。

## 9. Typora 兼容基线

参考策略：

- Typora 只作为用户已熟悉的黑盒交互与兼容基线，重点对照单画布、常用 Markdown 编辑和文件工作流；不复刻全部设置、主题 DOM 或导出格式，也不依赖其私有实现。
- 开源 Markdown 应用用于比较架构、边界案例和可访问性；采用任何代码或资源前必须单独完成许可证与来源审查。
- 参考产品之间行为不一致时，以本规格的 UX-* 和 AC-* 为准，不能由实现代理选择自己熟悉的一套。

### 9.1 单画布编辑

P0 必须支持以下基础内容的同画布阅读与编辑：

- 段落、ATX 标题、水平线；
- 粗体、斜体、删除线、行内代码；
- 有序/无序/任务列表与嵌套；
- 引用块、围栏代码块和语言标记；
- 内部/外部链接、图片；
- GFM 表格；
- YAML front matter 原样保留；精确编辑使用显式源码模式；
- 行内与块级数学公式原样保留；精确编辑使用显式源码模式，安全渲染进入 P1；
- Mermaid 围栏代码块与渲染预览；
- 常用转义字符和原始 HTML 的安全 raw 节点；精确编辑使用显式源码模式。

脚注和 `[TOC]` 目录标记进入 P1；P0 必须保留原文，可视模式以不可执行 raw 节点表示，精确编辑使用显式源码模式，不能删除或重新解释。

普通文档在可视模式中直接编辑上述结构；未支持语法可以显示为保留原文的可视 raw 节点，但不得因为光标经过而展开整个源码范围。精确 Markdown 一律通过显式源码模式编辑。

### 9.2 编辑表面切换

- 新打开的 `normal` 文档默认 `visual`；`sourceOnly` 固定为 `source`。
- 可视模式与源码模式由用户通过明确控件或 `Primary+/` 切换，选择保存在当前 Tab 的 View State。
- 标题、列表、链接、代码块、Mermaid 和表格不得依据光标位置自动切换表面或替换成源码 DOM。
- 模式切换不得移动导航历史、标记 dirty、提交正文 transaction 或污染 Undo。

### 9.3 编辑惯例

- 在列表项末尾回车创建同级项；空列表项再次回车退出列表。
- 代码围栏内不自动解释 Markdown。
- 成对标记、括号和围栏的自动补全必须可撤销，且不得与输入法组合输入冲突。
- 粘贴纯文本默认保留文本；粘贴 URL 到选中文本时可以创建链接，但必须支持撤销。
- 撤销/重做以用户意图为事务单位，装饰显隐和异步渲染不得污染撤销栈。

### 9.4 源码保真

- 未编辑的文档执行打开和保存，字节内容必须不变（平台明确要求的首次编码修复除外，并需用户确认）。
- 仅打开、导航、选择、滚动或切换模式不得触发 serializer。
- 首次可视正文编辑后 Milkdown/ProseMirror serializer 可以规范化整篇等价 Markdown；源码模式仍按文本 transaction 精确修改。
- 未识别语法至少在未编辑时原样往返，并始终可通过显式源码模式处理；不得在打开阶段悄悄删除。

## 10. 浏览器式导航

对应能力标记：`navigation.tabs`、`navigation.history`。

### 10.1 链接分类

所有入口——正文链接、文件树、搜索、大纲、未来反向链接——必须通过同一资源路由语义解析：

| 目标                           | 默认行为                                       |
| ------------------------------ | ---------------------------------------------- |
| 当前文件 `#heading`            | 当前标签跳到标题并加入历史                     |
| 本地 `.md` / `.markdown`       | 当前标签打开并加入历史                         |
| 本地 Markdown + `#heading`     | 打开文件并定位标题，作为一个历史项             |
| 本地图片/PDF/其他受支持资源    | 应用内资源页或系统预览，行为需一致             |
| `http:` / `https:` / `mailto:` | 使用系统默认应用打开，不加入当前 Tab 历史      |
| 不存在、越权或无法解析目标     | 在当前打开方式中显示可恢复错误页，保留原始目标 |

标题锚点匹配应兼容常见 Markdown slug 规则。存在重名标题时，按文档顺序定位第一个，并提供同名提示；未来可加入稳定块锚点。

### 10.2 打开方式

| 操作                                        | 行为                                                          |
| ------------------------------------------- | ------------------------------------------------------------- |
| 普通单击可视链接                            | 当前 Tab 打开                                                 |
| `Primary+单击`                              | 后台新 Tab                                                    |
| `Primary+Shift+单击`                        | 前台新 Tab                                                    |
| 鼠标中键                                    | 后台新 Tab                                                    |
| 右键/上下文菜单                             | 当前打开、新前台/后台 Tab、P1 右侧分栏、复制链接、Finder 显示 |
| `Primary+Enter`（源码态链接或键盘焦点链接） | 新前台 Tab；可在快捷键设置中调整                              |

可视编辑中的链接仍是可导航链接，必须使用明显蓝色下划线并按上表进入应用 Router；不得因“正在编辑”而退化为普通文本。只有用户已显式进入整页源码模式时，单击 Markdown 链接语法才只移动光标，打开动作使用键盘命令或链接工具。

### 10.3 前进与后退

每个 Tab 独立维护 `back / current / forward`：

- 打开新目标时，把当前资源及最新 View State 压入 back，并清空 forward。
- 后退/前进只移动历史指针，不创建新历史。
- 锚点跳转也属于可后退的导航。
- 普通输入、光标移动、折叠和滚动只更新当前历史项，不创建历史。
- 点击当前完全相同的资源和锚点不创建重复历史项。
- 历史目标已删除时显示错误页；用户仍可继续后退或前进。

View State 至少包含：

- 当前 `visual/source` 编辑表面；
- 光标和选区；
- 顶部可见 Markdown 块的稳定标识；
- 该块内像素偏移；
- 折叠状态；
- 必要时的编辑/阅读子模式。

不得只保存绝对 `scrollTop`。图片和 Mermaid 异步改变布局后，应先按块锚点恢复，再在布局稳定后校正一次。

### 10.4 标签页规则

- 新 Tab 插在当前 Tab 右侧；后台打开不改变焦点。
- 关闭当前 Tab 后优先激活最近使用的相关 Tab；若没有记录，则激活左侧邻居，再选右侧。
- `Primary+Shift+T` 按关闭顺序恢复标签及其完整历史和 View State。
- P1 拖动可重排 Tab；移动时不得改变其历史。
- `Primary+1…8` 选择对应 Tab，`Primary+9` 选择最后一个 Tab。
- P0 不引入“预览 Tab/双击固定”这种额外状态，避免与浏览器模型冲突。

## 11. Peek 快速预览（P1）

对应能力标记：`navigation.peek`。

- 指针停在可导航链接上并按住 `Space`，或键盘聚焦链接后执行“Peek”，显示目标标题附近的只读浮层。
- Peek 不改变当前 Tab、焦点历史或前进/后退栈。
- 浮层显示目标文件名、标题、目标段落上下文，以及“当前打开”“新 Tab 打开”“右侧打开”。
- 松开 `Space`、按 `Escape` 或执行打开操作后关闭。
- 同一时刻只存在一个 Peek；快速经过多个链接时应防抖并取消过期加载。
- 目标不存在时在浮层内显示断链原因和复制目标操作。
- Peek 默认只读；要编辑必须转为正常打开，避免隐藏的文档会话获得焦点。

## 12. 分栏（P1）

对应能力标记：`layout.splitView`。

- P1 支持最多左右两个 Tab Group；每组有自己的活动 Tab 和导航历史。
- “在右侧打开”在无分栏时创建右栏，已有右栏时复用右栏当前组。
- 同一文件在两栏打开时共享文本，不共享光标和滚动。
- 命令作用于拥有键盘焦点的栏；活动栏必须有不只依赖颜色的视觉标识。
- 分隔条可拖动、键盘调整，并支持“一键平均”“关闭当前栏”。
- 关闭一栏时，其余栏扩展；dirty 文档按 Document 会话规则处理。
- 会话恢复应保存分栏比例、每栏 Tab 和活动焦点。

P2 可以扩展为更多网格，但不允许 P1 为任意树形布局增加不必要复杂度。

## 13. 图片粘贴

对应能力标记：`clipboard.imagePaste`。

### 13.1 默认流程

1. 粘贴事件包含 `image/*` 时，图片优先于剪贴板中的 HTML 或 Base64 文本。
2. 应用立即拦截默认粘贴，先把图片安全写入资源目录。
3. 写入成功后才在光标处插入相对链接，例如：

   ```md
   ![screenshot](./assets/paste-20260829-143022-a13f9c2e.png)
   ```

4. 链接插入完成后，图片按单画布规则显示，光标位于图片节点之后。

默认资源目录为当前文档旁的 `assets/`，文件名包含时间和内容摘要以避免冲突。目录和命名模板可在 P1 设置中调整。

### 13.2 未命名文档

- 未保存文档的图片先写入应用 staging 区，并在编辑器中显示稳定的临时资源引用。
- 第一次保存文档时，应用必须先确定资源目录、完成移动/复制和链接重写，再报告保存成功。
- 用户取消首次保存时，图片继续可见，不能产生断链。
- 恢复未命名文档时必须同时恢复 staging 图片。

### 13.3 反馈、撤销和失败

- 写入超过 150ms 时显示非阻塞“正在保存图片”状态；用户仍可操作其他 Tab。
- 写入失败时不得插入 Markdown 链接，并提供“重试”“选择其他目录”“复制错误详情”。
- 撤销图片粘贴只移除 Markdown 节点；资源文件不立即自动删除，因为其他链接或重做可能仍需使用。
- P1 提供“清理未引用资源”，默认预览清单并要求确认。
- 剪贴板同时包含图片和用户确实需要的文本时，提供“粘贴为纯文本”命令绕过图片优先规则。
- 资源目录只读、磁盘已满、权限过期和名称冲突必须有可区分错误。

### 13.4 大 Base64 粘贴

- 大 `data:image/...;base64` 文本必须在进入编辑器事务和撤销栈之前识别。
- 若内容可安全解码，提示“保存为图片并插入链接”或“取消”。
- 解码失败时只允许复制错误详情或取消，不提供会让主界面失去响应的“仍然粘贴”。
- 普通短 data URI 的阈值和策略由安全设计定义，但用户体验必须保持一致。

## 14. Mermaid 阅读与缩放

对应能力标记：`diagram.mermaidViewer`。

### 14.1 文内状态

- Mermaid 块在可视模式始终显示 SVG 预览，最大宽度适应正文，不裁掉内容；聚焦不会自动展开围栏源码。
- 悬停或键盘聚焦后出现工具栏：放大、复制源码；P1 增加导出 SVG/PNG。编辑原始围栏需显式切换整个 Tab 到源码模式。
- 单击预览或点击放大按钮打开查看器；关闭后恢复原可视节点焦点与滚动位置。
- production Tauri CSP 必须允许 Mermaid SVG 所需的内联样式，release 包中的节点、连线和文字必须清晰可读。

### 14.2 图表查看器

查看器必须提供：

- 以指针位置为中心的滚轮/触控板缩放；
- 鼠标/触控板拖拽平移；
- `+`、`-`、100%、适应窗口、重置；
- 当前缩放百分比；
- `Escape` 关闭并恢复原文焦点和滚动位置；
- 键盘方向键平移，`+`/`-` 缩放，`0` 适应窗口，`1` 恢复 100%；
- 10%～1600% 的合理缩放范围，超界时保持在边界而非抖动。

查看器应使用矢量缩放。只有用户主动导出 PNG 时才允许栅格化。

### 14.3 错误与安全

- 单个 Mermaid 语法错误只替换该块预览，显示行列、简洁错误和“切换到源码”。
- 超时、节点过多或资源限制不得阻塞文档其他区域。
- 重新编辑后自动重试渲染；旧异步结果不得覆盖新源码结果。
- 文档内容视为不可信，图表中的脚本、事件处理和不允许的外部资源不能执行。

## 15. 表格体验

对应能力：P0 直接单元格编辑；P1 高级表格工具。

现有真实文档表格密集，因此表格属于 P0 阅读能力，而不是后置装饰。

### 15.1 P0 真表格编辑

- 表格始终以语义化网格显示，支持横向滚动，不缩小到不可读字号。
- 点击单元格直接编辑内容；不得展开整个 pipe 源码或改变文档块高度。
- `Tab` / `Shift+Tab` 在逻辑单元格间移动；表格选择和编辑必须可由键盘完成。
- 只有显式切换整个 Tab 到源码模式才显示 pipe 语法；源码态 `Tab` / `Shift+Tab` 遵循 CodeMirror 规则。
- 列对齐必须按 GFM 分隔行呈现；渲染态对齐与源码一致。
- 文档未发生正文编辑时绝不能自动对齐空格、重排分隔线或改写转义管道符；首次可视编辑后 serializer 可以规范化等价 pipe Markdown。
- 复杂或解析失败的表格不得猜测并破坏数据；保留原文并提示用户显式使用源码模式。

### 15.2 P1 高级表格工具

P1 在 P0 单元格直接编辑之上增加：

- 末单元格 `Tab` 可追加一行；
- 插入/删除/移动行列；
- 设置左/中/右对齐；
- 表头切换、复制行列、粘贴 TSV/CSV；
- 工具栏操作完成后只改写该表格，且先提供可撤销事务。

排序、筛选、公式和大数据表格虚拟化属于 P2 或专用资源页，不写入标准 Markdown，除非用户明确导出结果。

## 16. 大文件与异常输入体验

对应能力标记：`safety.largeInputGuard`。

产品不以专业超大文件编辑器为目标。打开结果固定为 normal、sourceOnly、blocked 三类主结果；二进制或不支持编码保留为拒绝终态：

1. **正常模式**：完整 Markdown 编辑和装饰；
2. **sourceOnly 大文本模式**：使用 CodeMirror 保留文本编辑、查找和保存，暂停 Milkdown/ProseMirror、Mermaid、图片解码、拼写和高成本投影；
3. **安全页面**：超长单行、大 Base64 或其他高风险输入不进入主编辑器。
4. **Unsupported**：二进制、无法无损支持的编码或超过硬上限的文件不承诺内置编辑，只提供原因、外部程序打开与取消；不提供会误导为安全可修复的 Base64 修复动作。

安全页面必须说明：

- 检测到的原因与大致位置/大小；
- 原文件没有被修改；
- 可用操作：查看预检摘要、备份后提取图片、备份后删除异常节点、用外部工具打开、取消；
- 所有会修改文件的修复操作都先展示目标文件和备份位置。

阈值由安全与性能设计统一维护，UI 不散落硬编码。正常文档不显示相关设置或警告。

## 18. 无障碍与国际化

### 18.1 键盘与屏幕阅读器

- 所有按钮、Tab、菜单、树节点、错误操作和查看器控件均可纯键盘访问。
- 标签页使用标准 tablist 语义，文件树使用 tree 语义，渲染表格使用 table 语义。
- 当前标签、活动分栏、dirty、只读和错误状态不能只依赖颜色表达。
- Mermaid 预览提供“图表，名称，打开查看器，切换到源码模式”的可访问名称；显式源码模式始终是等价文本出口。
- 模态查看器必须圈定焦点，关闭后把焦点还给触发控件。
- 保存失败、图片完成、断链和渲染错误通过礼貌级 live region 宣告，不抢走编辑焦点。

### 18.2 视觉与运动

- 文本和关键控件达到 WCAG 2.2 AA 对比度。
- 支持至少 80%～200% 界面缩放，正文不应因放大产生不可访问的横向整体滚动；代码和大表格可局部横向滚动。
- 焦点环清晰，并与选区、搜索命中区分。
- 尊重系统“减少动态效果”；Tab、Peek 和错误提示不依赖大幅动画传达状态。
- 点击目标适合桌面精确指针，同时不能小到难以使用；图标必须有文字提示。

### 18.3 语言

- P0 界面可先提供简体中文，但所有字符串必须可本地化，不拼接不可翻译句子。
- 文件内容语言不决定界面语言；不自动翻译标题、链接或错误中的用户路径。
- 日期、数字和快捷键按系统区域格式显示。

## 19. 错误、空状态与冲突

### 19.1 空状态

| 状态            | 必须提供的下一步                                    |
| --------------- | --------------------------------------------------- |
| 未打开工作区    | 打开文件夹、打开文件、最近工作区                    |
| 空文件夹        | 新建 Markdown、在系统文件管理器中显示已授权工作区根 |
| 新空文档        | 轻量占位提示；开始输入后消失                        |
| 无标签页        | 显示新标签页页面，不留下纯空白窗口                  |
| 空大纲          | 说明“此文档没有标题”，不显示错误                    |
| 搜索无结果      | 显示查询条件及清除/修改操作                         |
| 无后退/前进历史 | 控件禁用，并有可访问说明                            |

### 19.2 常见错误

| 错误              | UX 要求                                            |
| ----------------- | -------------------------------------------------- |
| 文件不存在/已移动 | 保留目标路径；重试、定位文件、从历史移除           |
| 工作区权限失效    | 重新授权、选择其他位置；未保存内容继续保留         |
| 保存失败/磁盘已满 | 明确标记未保存；重试、另存为、复制恢复稿           |
| 文件只读          | 只读横幅；另存为或重新获取权限                     |
| 外部修改          | 比较、重新加载、保留本地、另存为；不得静默覆盖     |
| 断链              | 显示解析后的目标；搜索同名文件、编辑链接、复制目标 |
| 图片写入失败      | 正文不插入无效链接；重试或换目录                   |
| Mermaid 错误      | 只影响当前块；可显式切换到源码模式、复制错误       |
| 恢复稿存在        | 展示原文件与恢复版本的时间和差异入口               |

错误消息先说发生了什么和内容是否安全，再给操作；技术详情默认折叠但可复制。不可恢复错误必须保留恢复稿位置。

### 19.3 外部文件变更

- 文件未 dirty 时，可自动重新加载，但应以非打扰方式提示，并尽量保持 View State。
- 文件已 dirty 时，绝不能自动覆盖内存内容。
- 冲突界面至少允许查看差异、保留本地、采用磁盘版本和另存为。
- 同一 Document 的所有视图必须显示一致冲突状态。

### P0：可替代日常 Typora 工作流

- GFM 表格直接单元格编辑和 Tab/Shift+Tab 导航；
- 大输入预检、大文本模式、安全页面；

## 21. 验收标准

以下标准使用发布构建，在基准 Apple Silicon Mac（16GB 内存）执行；性能测试须记录机型、系统和语料版本。Windows/Linux 移植后使用同等档次机器建立独立基线。每条 `AC-*` 后的“覆盖”字段指向其验证的稳定 `UX-*` 需求；一项需求可以由多个验收场景共同覆盖。

### 21.1 内容与编辑

- **AC-EDIT-001**（覆盖 `UX-FILE-001`、`UX-FILE-002`）：从真实回归语料随机抽取至少 50 篇文档，打开后不编辑直接保存，文件逐字节零差异。
- **AC-EDIT-002**（覆盖 `UX-EDIT-001`、`UX-EDIT-002`、`UX-EDIT-003`）：标题、列表、链接、代码块、表格和 Mermaid 在可视模式中输入与移动光标时不泄露 Markdown 标记、不改变块高，中文 composition 不丢字、不重复提交、不跳光标。
- **AC-EDIT-003**（覆盖 `UX-EDIT-003`）：连续撤销/重做覆盖输入、格式化、图片粘贴和表格事务，最终内容与初始/最终快照一致。
- **AC-EDIT-004**（覆盖 `UX-FILE-002`、`UX-EDIT-001`）：未知 Markdown 扩展打开、切换模式、未编辑保存保持零差异；首次可视正文编辑后的 serializer 结果可重开。
- **AC-EDIT-005**（覆盖 `UX-EDIT-001`、`UX-DOC-001`）：每个 Tab 独立恢复 `visual/source`、选择和滚动；切换模式不 dirty、不进入 Undo。
- **AC-EDIT-006**（覆盖 `UX-EDIT-003`）：可视输入一个字符后不等待 timer 立即保存，磁盘包含最后字符。
- **AC-FIND-001**（覆盖 `UX-FIND-001`）：中文/Emoji/大小写 literal 可查找并上下遍历；一次 Undo 可恢复对应 replace transaction，10 MiB sourceOnly 中仍可完成。
- **AC-TABLE-001**（覆盖 `UX-TABLE-001`、`UX-A11Y-001`）：表格单元格可直接输入、选择并以 Tab/Shift+Tab 导航，不出现 pipe 源码或块高跳变。
- **AC-TABLE-002**（覆盖 `UX-TABLE-002`）：未编辑文档中的表格不被自动对齐或重写；首次可视编辑后的等价 serializer 输出可保存和重开。
- **AC-TABLE-003（P1）**（覆盖 `UX-TABLE-003`）：末格追加行和高级行列操作形成单一可撤销事务。
- **AC-MATH-001（P1）**（覆盖 `UX-MATH-001`）：有效的行内/块级公式可渲染，并允许用户显式切换到源码模式进行精确编辑；一个无效公式只显示局部错误，不影响正文输入和其他公式。

### 21.2 导航与会话

- **AC-DRAFT-001**（覆盖 `UX-DRAFT-001`、`UX-KEY-001`）：重复一次新建 intent 只出现一个空白 dirty 草稿；取消关闭保持原稿，选择“不保存”后草稿、checkpoint 和 staging 不再出现在恢复中心，首次 Save As 则保留当前文档身份和有效资产链接。
- **AC-WORKSPACE-001**（覆盖 `UX-WORKSPACE-001`、`UX-NAV-001`）：文件树、当前文档大纲和 Quick Open 均可纯键盘选择；watcher overflow 后多页重扫未完成时旧树保持完整，完成后一次更新；所有结果遵循同一 current/new-tab 路由；空工作区可用显式动作在系统文件管理器中显示已授权根。
- **AC-NAV-001**（覆盖 `UX-NAV-001`、`UX-NAV-002`）：A 文档链接跳到 B，再跳到 C，连续后退两次依次回到 B 和 A 的原阅读位置，前进可逆。
- **AC-NAV-002**（覆盖 `UX-NAV-004`、`UX-TAB-001`）：`Primary+单击` 在后台新 Tab 打开，焦点、选区和当前 Tab 历史不变。
- **AC-NAV-003**（覆盖 `UX-DOC-001`、`UX-TAB-002`）：两个 Tab 打开同一文件；一处编辑后另一处看到相同文本，但光标和滚动位置保持独立。
- **AC-NAV-004**（覆盖 `UX-NAV-003`）：图片/Mermaid 异步完成布局后，历史恢复位置误差不超过一个可见正文行，并在校正时无明显闪跳。
- **AC-NAV-005（P1）**（覆盖 `UX-TAB-003`）：关闭并恢复 Tab 后，Tab 的当前资源、完整历史和 View State 恢复。
- **AC-NAV-006（P1）**（覆盖 `UX-TAB-004`）：拖动重排 Tab 后，每个 Tab 的当前资源、完整历史和 View State 均不变。
- **AC-RECOVERY-001**（覆盖 `UX-SESSION-001`、`UX-TAB-002`）：应用异常退出后未保存稿可恢复；若退出发生在资源打开期间，该资源下一次不自动进入主编辑器。
- **AC-SESSION-001（P1）**（覆盖 `UX-SESSION-002`、`UX-TAB-003`）：重新启动或恢复关闭 Tab 后，Tab 顺序、完整历史、View State 和布局可恢复；分栏时左右各自活动 Tab 与最后聚焦 Pane 不丢失。

### 21.3 图片与 Mermaid

- **AC-IMAGE-001**（覆盖 `UX-IMAGE-001`）：粘贴 4K 截图后生成唯一资源文件和相对链接，Markdown 中不存在 Base64。
- **AC-IMAGE-002**（覆盖 `UX-IMAGE-001`、`UX-ERROR-001`）：模拟权限拒绝、磁盘满和路径冲突时，正文及撤销栈不出现无效图片链接，且可重试或换目录。
- **AC-IMAGE-003**（覆盖 `UX-IMAGE-002`、`UX-SESSION-001`）：未命名文档粘贴图片、退出异常、恢复并首次保存后，图片可见且链接有效。
- **AC-DIAGRAM-001**（覆盖 `UX-DIAGRAM-001`、`UX-A11Y-001`）：超宽 Mermaid 可通过按钮和键盘打开查看器，缩放、平移、适应窗口、100% 和退出均有效。
- **AC-DIAGRAM-002**（覆盖 `UX-DIAGRAM-002`）：一个 Mermaid 块语法错误或超时不影响正文输入、其他图表和 Tab 切换。
- **AC-DIAGRAM-003**（覆盖 `UX-DIAGRAM-001`）：退出查看器后焦点回到触发块，原文滚动位置不变。

### 21.4 安全与恢复

- **AC-SAFE-001**（覆盖 `UX-IMAGE-003`、`UX-SAFE-001`）：粘贴约 10MiB 单行 Base64 时，在编辑器事务前拦截；文档长度、dirty 状态和撤销栈不变。
- **AC-SAFE-002**（覆盖 `UX-SAFE-001`）：直接打开含约 10MiB 单行 Base64 的文件时，在 1 秒目标时间内显示安全页面，主界面和其他 Tab 可操作，全文不进入 WebView 主编辑器。
- **AC-SAFE-003**（覆盖 `UX-SESSION-001`、`UX-ERROR-001`）：保存过程中强制结束应用，原文件仍完整；重启后可发现恢复稿或完成态。
- **AC-SAFE-004**（覆盖 `UX-SAFE-002`）：修复动作修改原文件前创建可定位备份；中途失败仍能恢复原文件。
- **AC-SAFE-005**（覆盖 `UX-SAFE-001`）：二进制、无损不支持编码和严格大于 32 MiB 的文件分别进入 Unsupported，正文不进入 EditorView，且 UI 不把它们显示为可执行 Base64 修复的 SafetyBlocked。

### 21.5 性能

- **AC-PERF-001**（覆盖 `UX-PERF-001`）：约 250KiB 的真实 Markdown 冷打开到可输入目标 `<500ms`。
- **AC-PERF-002**（覆盖 `UX-PERF-001`）：任意已缓存、已打开文档/资源的 Tab 切换到首帧稳定 p95 `<100ms`；已缓存 Back 恢复定位 p95 `<150ms`，两项分别记录且不得互相替代。
- **AC-PERF-003**（覆盖 `UX-PERF-001`）：普通文档连续输入时，按键到可见更新 P95 目标 `<50ms`，无持续掉帧或输入积压。
- **AC-PERF-004**（覆盖 `UX-PERF-001`、`UX-PERF-002`）：包含大量表格的长文档连续滚动时，不因离屏表格或 Mermaid 全量重绘造成秒级停顿。
- **AC-PERF-005**（覆盖 `UX-PERF-002`、`UX-IMAGE-001`）：图片落盘超过 150ms 即出现反馈；常见 4K 截图在本地磁盘完成并插入链接的 P95 目标 `<1s`。

性能目标是发布门槛的方向值；若硬件或系统 API 导致偏差，必须提供测量数据并更新统一基线，不能通过删除测试掩盖回归。

### 21.6 无障碍与平台

- **AC-A11Y-001**（覆盖 `UX-A11Y-001`）：不使用鼠标即可完成打开工作区、选择文件、编辑、保存、新开 Tab、后退/前进、图片错误恢复和 Mermaid 查看器操作。
- **AC-A11Y-002**（覆盖 `UX-A11Y-001`、`UX-A11Y-002`）：VoiceOver 能读出 Tab 名称/选中/dirty 状态、文件树层级、表格结构和 Mermaid 查看入口。
- **AC-A11Y-003**（覆盖 `UX-A11Y-001`）：200% 界面缩放下核心操作可用，正文不被固定尺寸遮挡。
- **AC-A11Y-004**（覆盖 `UX-A11Y-002`）：浅色、深色和增加对比度环境下，焦点、选中、错误与活动栏状态均可区分。
- **AC-KEY-001**（覆盖 `UX-KEY-001`）：第 17 节 P0 快捷键在系统菜单、帮助和对应焦点域中一致；重复绑定测试可确定性选择命令并显示冲突。
- **AC-PLATFORM-001**（覆盖 `UX-PLATFORM-001`、`UX-EDIT-003`）：macOS 中文输入法、触控板和系统菜单通过回归；Finder/文件关联/文件或目录拖入只产生 grant-backed target，批量文件按序开 Tab 且最终聚焦最后一个成功项；Windows/Linux 移植时同一行为矩阵逐项通过或记录平台降级。

## 22. 面向多代理实现的 UX 契约

为允许多个子代理并行实现，各能力只通过以下用户可观察契约交汇：

| 能力域             | 对外契约                                                   | 不得自行改变                               |
| ------------------ | ---------------------------------------------------------- | ------------------------------------------ |

## 23. 已确认默认与变更原则

为避免并行实现被产品选择阻塞，当前默认已经固定：

- P1 渲染行内/块级数学、脚注和 `[TOC]`；P0 原样保留源码并允许编辑。
- 截图默认替代文本为 `screenshot`，不弹阻塞对话框；图片工具条提供快速修改替代文本。
- 大文本模式与阻止页阈值由文件预检集中配置，产品层只依赖 normal、sourceOnly、blocked/unsupported outcome，不在各模块复制数值。
- dirty 已保存文件失去最后一个可见视图时，保留在“未保存文档”列表并显示一次非阻塞提示，不弹对话框。
- P1 自动保存默认关闭，由用户按工作区或全局开启。

任何变更若影响文件内容、导航历史、撤销、保存安全或跨平台快捷键，**MUST** 先更新本规格、稳定需求 ID 的描述和对应验收用例。单纯视觉调整 **MAY** 在不改变语义的前提下迭代。
